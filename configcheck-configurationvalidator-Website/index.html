configcheck-configurationvalidator

Every part is tried against the same unchanging shape here: one configuration held against one JSON schema, pass or fail with no degrees between, and where it does not conform, the failure and its location are reported.

Configuration first, schema second

python3 main.py CONFIG_FILE SCHEMA_FILE [--format json|yaml|ini] [--log-level LEVEL]

Two required positionals. The configuration loads before the schema, so when both files are broken the configuration error is the one reported and the schema file is not opened until the configuration has parsed.

Format from the last suffix only

Format comes from --format or is inferred from the last suffix only, so a file whose name ends in a backup suffix needs an explicit --format.

INI values all arrive as strings

INI is read with configparser: every value arrives as a string, so a schema requiring an integer fails an otherwise correct INI file, and the DEFAULT section's keys fold into every section, so a schema forbidding extra keys can fail on keys the file never wrote under that heading.

Only a valid configuration exits 0

Only a valid configuration exits 0. A missing file, an unrecognised format, an invalid schema, and a validation failure all exit 1.
