Two Files, Both Required

configcheck-configurationvalidator takes two files. The first file is a configuration in JSON, YAML, or INI. The second file is a schema in JSON. The tool checks the configuration against the schema. It reports invalid data types. It reports missing fields. It reports violations of the constraints the schema defines. A valid configuration prints the words Configuration is valid. and exits 0. An invalid configuration prints the failure and its location, and exits 1.

The Command in Full

Both positionals are required. The schema file is required as well as the configuration file. There is no mode in which the schema is optional. This page states that plainly, because other validators in this fleet offer one. This one does not.

--formatTakes json, yaml, or ini. When it is omitted, the format is inferred from the file extension.

What Each Format Does to Its Values

JSON is read with the standard JSON parser. YAML is read with a safe load. INI is read with the standard configuration parser, and every INI value arrives as a string.

INI Values Are Always Strings

An INI file therefore needs a schema that expects strings. A schema that requires an integer will fail an INI file whose sections are otherwise correct. The INI reader also folds the default section keys into every section. A schema that forbids extra keys can therefore fail on keys the file did not write under that section heading. Format inference reads the last suffix only. A file whose name ends in a backup suffix needs an explicit --format value.

Only Valid Exits 0

The Configuration Is Read Before the Schema

The configuration is loaded before the schema. When both files are broken, the configuration error is the one reported. The schema file is not opened until the configuration has parsed.

A missing file exits 1. An unsupported or unrecognised format exits 1. A schema that is itself invalid exits 1, with a schema error message. A validation failure exits 1, with the failure and its location. Only a valid configuration exits 0.

# configcheck-ConfigurationValidator

Validates configuration files (JSON, YAML, INI) against a schema definition provided as input. Reports errors for invalid data types, missing fields, or violations of defined constraints.

## Install

`git clone https://github.com/ShadowGuard-AI/configcheck-configurationvalidator`

## Usage

`python3 main.py CONFIG_FILE SCHEMA_FILE [--format json|yaml|ini] [--log-level LEVEL]`

## Parameters

- `-h`: Show help message and exit

- `config_file`: Path to the configuration file (JSON, YAML, or INI). Required.

- `schema_file`: Path to the schema file (JSON). Required.

- `--format`: Specify the configuration file format (json, yaml, or ini). If omitted, it will be inferred from the file extension.

- `--log-level`: Set the logging level. Choices: DEBUG, INFO, WARNING, ERROR, CRITICAL. Default: INFO.

## Verified behavior

- A JSON configuration matching its schema exits 0 with "Configuration is valid."

- A JSON configuration violating its schema exits 1 with the validation failure and its location.

- INI limitation, verified by run: INI files must have section headers, and every INI value is read as a string, so a schema requiring an integer fails for INI values even when the section structure matches. Use string schemas for INI files, or JSON or YAML for typed values.
